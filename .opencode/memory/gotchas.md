# Gotchas
- scripts/smoke.ts hardcodes an absolute Chromium path and /tmp/opencode/shots: edit before use.
- web/scss/app.scss is orphaned (not linked by index.html).
- web/css/ is generated and gitignored: build SCSS once on a fresh checkout or the app is unstyled.
- src/http/server.ts ignores DB_PATH (fixed by T1); MCP and seed scripts honor it. Keep them in sync.
- Electrobun docs on the web and old tutorials may describe v1: this repo's snapshot is v2.x. See guides/migrating-to-v2.mdx.
- study.undo() is global (reverts the most recent review of any card); a single-user assumption.
- changefeed.subscribe() starts at current MAX(id): a new SSE stream never replays older changes.
- Electrobun on Linux needs libayatana-appindicator3.so.1 at launch (Arch: `sudo pacman -S libayatana-appindicator`); missing it fails with "Failed to open native wrapper ... libNativeWrapper.so".
- Linux dev launch logs `X11 Error: GLXBadWindow (code 170)` even though the window opens (verified via xprop WM_NAME). Application menus are unsupported on Linux. Keep UI controls in the webview.
- Hutch `build.copy` destinations are relative to `Resources/app/`, not `Resources/`. The bundled main entry is `Resources/app/bun/index.js`, so schema.sql is copied to `bun/schema.sql` and the web build to `dist/web`.
- Bundled `import.meta.url` differs from the dev source tree: src/http/static.ts must resolve both repo-root and `Resources/app/` layouts (webDir helper).
- A preBuild hook (`scripts/electrobun-pre-build.ts`) runs `bun run build:web` so the self-contained UI exists before Hutch copies it; without it the webview gets ENOENT on /index.html.
- Navigation rules are allow-by-default: use `["^*", "<our-origin>/*"]` (deny all, then allow). `sandbox: true` removes all native RPC from the webview, so external links currently do not open in the system browser — add a deliberately narrow openExternal handler in Phase 2 if needed.
- T13 Linux packaged build (`hutch run build`) works: self-extractor installs to ~/.local/share/local.ministudyui.desktop/stable/app and launches; WebKitGTK rendered the UI correctly in a screenshot. Cross-OS verification (Windows/macOS) is blocked here — Hutch builds only for the host OS, so native runners are required.
